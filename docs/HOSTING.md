# Hosting KurumanMarketPlace online (Render + Neon)

About 30–45 minutes the first time. Everything here uses **free plans** and **synthetic demo data only** — no
real customers until the privacy notice's responsible party is named (see `/privacy`).

What you end up with:

| Piece | Where | Address |
|---|---|---|
| Website + API (one service) | Render | `https://kurumanmarketplace.onrender.com` (Render may add letters if the name is taken) |
| AI category model | Render | `https://kurumanmarketplace-ai.onrender.com` |
| Database (PostgreSQL) | Neon | a connection string, kept secret |

The file `render.yaml` in the project describes both Render services, so Render sets them up for you.

---

## 1. Database on Neon

1. Go to **https://neon.tech** → **Sign up** → *Continue with GitHub*.
2. Create a project: name `kurumanmarketplace`, Postgres version **17 or newer**, region **AWS Europe (Frankfurt)**
   (closest to the Render region we use).
3. On the project dashboard click **Connect**, and copy the **connection string**
   (starts with `postgresql://` and ends with `?sslmode=require`). Keep it private — it is a password.

### Create the tables and demo accounts (from your laptop)

Open a **new** PowerShell terminal in VS Code. The prompt should end in `Kuruman_MarketPlace>`.

```
cd server
```

Now the prompt ends in `Kuruman_MarketPlace\server>`. Paste your Neon connection string between the quotes:

```
$env:DATABASE_URL = "postgresql://...your Neon string..."
```
```
$env:DATABASE_SSL = "true"
```

Choose a **private** demo passphrase (15+ characters) — not `Kuruman Oasis 2026`, because this repository is
public and anyone can read that one:

```
$env:SEED_PASSPHRASE = "your own private demo passphrase"
```
```
npm run db:setup
```
```
npm run db:seed
```

You should see "Database tables created successfully" and the list of demo accounts.

**Then close this terminal** (bin icon). Those settings only live in that terminal; closing it makes sure your
next `npm run db:setup` goes to your laptop's database, not to Neon.

## 2. Make two secrets

In any PowerShell terminal in the `server` folder, run this **twice** and keep both results:

```
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

- The first result is your hosted `DATA_ENCRYPTION_KEY`. Use a new one, not the one on your laptop.
- The second is spare, in case you need to replace the first.

(The AI token is generated by Render automatically.)

---

## 3. The two services on Render

1. Go to **https://render.com** → **Get Started** → *GitHub*. Allow access to the `Kuruman_MarketPlace` repository.
2. **New** → **Blueprint** → choose the repository. Render reads `render.yaml` and lists
   `kurumanmarketplace` and `kurumanmarketplace-ai`.
3. Render asks for the values marked secret. Fill in:

| Setting | Value |
|---|---|
| `DATABASE_URL` | your Neon connection string |
| `CLIENT_ORIGIN` | `https://kurumanmarketplace.onrender.com` (no slash at the end) |
| `PUBLIC_APP_URL` | the same address |
| `DATA_ENCRYPTION_KEY` | the secret from step 2 |
| `AI_SERVICE_URL` | `https://kurumanmarketplace-ai.onrender.com` |
| `PAYFAST_MERCHANT_ID` | from your Payfast sandbox |
| `PAYFAST_MERCHANT_KEY` | from your Payfast sandbox |
| `PAYFAST_PASSPHRASE` | your sandbox passphrase |
| `PAYFAST_NOTIFY_URL` | `https://kurumanmarketplace.onrender.com/api/payments/payfast/notify` |

4. **Apply**. The first build takes 5–10 minutes. When it says *Live*, open
   `https://kurumanmarketplace.onrender.com/api/health` — you should see `"status":"ok"`.

If Render gave a service a different address (e.g. `kurumanmarketplace-x7k2.onrender.com`), open that service →
**Environment**, correct `CLIENT_ORIGIN`, `PUBLIC_APP_URL`, `PAYFAST_NOTIFY_URL` and `AI_SERVICE_URL`, and save
(it redeploys by itself).

## 4. First sign-in, straight away

1. Open the website and sign in as **Support (071 000 0004)** with your private demo passphrase.
2. Open **Console** and set up your authenticator app **immediately**. The first person to do this controls the
   support account, so don't leave it for later. Do the same for Sipho (071 000 0007) if you'll use it.
3. Try the whole flow with the customer, seller and courier accounts.

## 5. Payfast on the hosted site

No tunnel is needed any more: Payfast can reach `PAYFAST_NOTIFY_URL` directly. Make one sandbox payment, then check
it was accepted. In Neon → **SQL Editor** run:

```
SELECT outcome, received_at FROM payment_events ORDER BY id DESC LIMIT 5;
```

- `applied` — all good.
- `rejected_source_ip` — Render put a different number of proxies in front of the app. In Render → the
  `kurumanmarketplace` service → **Environment**, change `TRUST_PROXY` from `1` to `2`, save, and pay again.

---

## 6. Things to know about the free plans

- **Render free services sleep** after 15 minutes without visitors; the next visit takes about a minute to wake
  them. **Open the site 2 minutes before you present.** While asleep, the background jobs (order expiry,
  notifications, clean-up) pause and catch up when it wakes.
- **Neon's free database also pauses** when idle and wakes on the first request (a few seconds).
- **Every `git push` to GitHub redeploys automatically.** Push only working, tested commits.
- **Resetting hosted data**: repeat section 1's commands (new terminal, set the three `$env:` lines, `db:setup`,
  `db:seed`, close the terminal). This wipes the hosted data, including the support authenticator set-up.

## 7. Later: Google Play Store

Once the hosted site works, it can be wrapped as an Android app with **PWABuilder** (https://www.pwabuilder.com):
enter the site's address and download the Android package. You'll need a Google Play developer account (one-off
US$25), a privacy policy address (`/privacy`, with the responsible party named) and a small `assetlinks.json` file
that PWABuilder generates, served by the website to prove the app is yours. Real payments need a live Payfast
account and must not go live with demo data.
